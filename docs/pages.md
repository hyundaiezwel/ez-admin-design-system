# 목업 페이지 구성

어드민 요소를 **한 번씩은 다 지나가게** 짠 목록이다. 화면을 늘리는 게 목적이 아니라
`@ezwel/ui` 토큰 · UI 라이브러리 컴포넌트 · Tabulator · ECharts가 실제로 물리는지 보는 게 목적이다.

## 그리드 원칙

**PoC 화면을 옮기지 않는다.** `vue-tabulator-grid-poc`는 요건을 검증하려고 토글과 계측을
붙여 둔 실험대다. 목업에는 **표가 필요한 자리에 표만** 들어간다.

PoC에서 가져오는 것은 값이 검증된 두 조각뿐이다.

| 가져옴 | 이유 |
|---|---|
| `pasteGuard.js` | 기본 파서가 숫자 컬럼에 문자열을 그대로 저장한다. 되돌리기도 안 된다 |
| `rowSelect.js` | 내장 `selectableRows`를 켜면 범위 복붙 모듈이 초기화조차 안 된다 |

화면은 `shared/grid/TabGrid.vue`에 **컬럼 원장과 데이터만** 넘긴다. 컬럼은
`shared/grid/<도메인>Columns.ts` 한 곳에 정의하고 화면은 어떤 세트를 보일지만 고른다.

편집·범위 복붙이 필요 없는 조회 전용 표는 `editable`을 끈다 — 끄면 체크박스 컬럼이
행 헤더 거터로 바뀌는 문제도 같이 사라진다.

### 4. 문의 답변 관리 (스파이크 화면)

이미 만들어 측정에 쓴 화면이다. 채널(웹/앱/전화/카카오/이메일) × 상태 5종 × 담당자 배정.

- 그리드: 제목·분류·담당자 인라인 편집, 범위 복붙(`pasteGuard` 규칙 적용), 상태·SLA는 뱃지
- SLA 잔여는 **색만으로 표시하지 않는다** — `12h 남음` / `3h 초과`로 부호와 단위를 남긴다
- 답변 등록은 슬라이드 패널, 담당자 일괄 변경은 모달
- 담당자 조건이 자동완성이라 **한글 IME 확인 지점**이다

### 5. 프로모션 등록·관리 (신규)

문의 관리가 "들어온 것을 처리"라면 이쪽은 "내보낼 것을 만드는" 화면이라 성격이 갈린다.
목업에서 확인할 것이 다르다.

- **기간 입력** — 시작~종료, 시작일 > 종료일 방어, '종료일 없음' 체크
- **대상 조건 빌더** — 등급·지역·가입시기 조합. 조건이 늘어나는 영역의 레이아웃
- **상태 전이** — 예약 → 진행 → 종료 / 중단. 상태에 따라 수정 가능 항목이 바뀐다
  (진행 중에는 기간 단축만 허용 같은 규칙)
- **미리보기** — 등록 중인 프로모션이 고객 화면에 어떻게 보이는지
- 그리드는 목록에서 쓰되 **진행 중 건은 인라인 편집 잠금** — 상태 기반 UI 제어 확인 지점

## 착수 전 미결

1. **UI 라이브러리** — `spike-report.md` 참조. PrimeVue 4 우세, v4 고정 리스크 수용 여부가 갈림길.
2. **`@ezwel/ui` 토큰 3건 수정** — 라이브러리와 무관하게 선행. `spike-report.md` §5.
3. **표가 두 벌이 된다** — `EzTable`(경량·조회)과 Tabulator(편집·대용량)의 경계.
   제안: 50행 이하 조회 전용은 `EzTable`, 그 밖은 Tabulator.
4. **컬럼 정렬(sort)** — 디자인 시스템 패턴 문서는 "제공하지 않는다"(서버 정렬 미확정 시
   페이징과 어긋남). Tabulator는 헤더 정렬이 기본이다. 문서를 고칠지 목업만 예외로 둘지.
